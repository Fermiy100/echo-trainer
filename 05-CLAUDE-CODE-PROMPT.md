---

Прочитай перед началом работы все файлы в `docs/` (`00-README.md`, `01-PRD.md`,
`02-ARCHITECTURE.md`, `03-DESIGN-SYSTEM.md`, `04-PROJECT-STRUCTURE.md`) — это полное
техническое задание на проект «Эхо». Дальше — сборка по этому заданию.

Контекст: школьный проект 7-классника для конкурса городского/регионального уровня с
защитой перед жюри. Дедлайн — январь. Бюджет на все платные API за всё время — **$10**,
не больше. Хостинг — только бесплатный Vercel (Hobby-план), без покупки домена.

Требования, которые нельзя нарушать:

1. **Ни один API-ключ не должен попасть в клиентский код.** Все вызовы к нейросетям —
   только через `app/api/*/route.ts`, ключи — только в переменных окружения.
2. **Everything must have a fallback.** Каждый внешний вызов оборачивается в цепочку
   «основной провайдер → платный резерв → локальный офлайн-пример» по схеме из
   `02-ARCHITECTURE.md`. Пользователь никогда не должен видеть голую техническую ошибку.
3. **Демо-режим (`/demo`) обязателен с первой же рабочей версии**, не как доработка
   в конце — это страховка всей защиты, работает полностью офлайн на данных из
   `public/demo-data/`.
4. **Дизайн — строго по `03-DESIGN-SYSTEM.md`**: цвета, шрифты (Nunito + PT Sans через
   Google Fonts), скругления, тени, иллюстрации с unDraw.co (перекрашенные под акцентный
   цвет `--accent`, а не дефолтный фиолетовый). Мобильный экран — основной, вёрстка от
   375px шириной, нижняя навигация из 3 пунктов вместо верхнего меню.
5. **Каждая внешняя вызов, который стоит денег, кэшируется** через Upstash Redis —
   одинаковый параграф не должен запрашиваться у платного API повторно.
6. Пиши код так, чтобы после `git push` в основную ветку Vercel мог задеплоить проект
   без ручных доработок — используй переменные окружения по списку из
   `02-ARCHITECTURE.md`, не хардкодь ключи и адреса.

Собирай по фазам, в конце каждой фазы должно быть что-то рабочее и задеплоенное:

- **Фаза 1** — каркас Next.js + Tailwind, главный цикл на моках (без реальных API):
  фото → объяснение → пересказ → проверка, плюс `/demo` на статичных данных.
- **Фаза 2** — подключить настоящие API (NVIDIA NIM, DeepSeek fallback, Groq для demo),
  Neon для истории, Upstash для кэша и rate-limit.
- **Фаза 3** — довести дизайн до `03-DESIGN-SYSTEM.md` полностью: иллюстрации, анимации,
  PWA-манифест и иконки.
- **Фаза 4** — онбординг с персонализацией примеров, экран истории/прогресса,
  публичная страница «О проекте» с реальными цифрами пилота (подставить плейсхолдеры,
  которые легко обновить после пилота вручную).

Если что-то в `docs/` неоднозначно или противоречит здравому смыслу для конкретной
реализации — спроси, не додумывай молча. Если вариант дешевле или так же бесплатен, но
проще в реализации при том же результате для пользователя — предложи его, объяснив
разницу в одном абзаце, прежде чем менять план.
